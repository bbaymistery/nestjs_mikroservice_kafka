POST /register — İstifadəçi Qeydiyyatı və Kafka Hadisəsi

İstifadəçi qeydiyyatdan keçən kimi AuthService onu Postgres bazasına yazır və eyni anda Kafka-ya "Xəbər" (Event) atır.

1
Sorğunun Qəbulu
Postman və ya Veb brauzerdən RegisterDto (email, password, name) Controller-ə daxil olur.
AuthServiceController
2
Şifrə & Baza Əməliyyatı
Emailin təkrar olub-olmaması yoxlanılır. Şifrə bcrypt ilə hash-lənir və Drizzle ORM ilə bazaya yazılır.
PostgreSQL 5432
3
Kafka-ya Hadisə (Emit) 🔥
user.registered mövzusuna mesaj göndərilir: "Bu adam qeydiyyatdan keçdi!"
Kafka Topic: user.registered
4
Sürətli Cavab
İstifadəçiyə dərhal cavab qaytarılır: { message: "User registered successfully", userId }.
HTTP 201 Created
auth-service.service.ts 
// 1. İstifadəçi bazaya yazılır
const [user] = await this.dbService.db
  .insert(users)
  .values({ email, password: hashedPassword, name })
  .returning();

// 2. Kafka Broker-ə (localhost:9093) Hadisə Göndərilir
this.kafkClient.emit(KAFKA_TOPICS.USER_REGISTERED, {
  userId: user.id,
  email: user.email,
  name: user.name,
  timestamp: new Date().toISOString(),
});

return { message: 'User registered successfully', userId: user.id };

💡 Niyə Kafka İstifadə Edirik?

  • Gözləmə Yoxdur: AuthService istifadəçiyə xoşgəldin emaili göndərməyi gözləmir. Xəbəri Kafka-ya atıb dərhal müştəriyə cavab qaytarır (millisaniyələr içində!).
  • Decoupling (Asılılığın kəsilməsi): AuthService gələcəkdə yaradılacaq EmailService və ya AnalyticsService-in harda olduğunu bilmir və bilməyə ehtiyacı da yoxdur.
  • İtmir: Kafka bu mesajı Docker-dəki diskdə etibarlı saxlayır. Email servisi sönülü olsa belə, sabah qalxanda bu mesajı oxuyub emailini atacaq.

POST /login — Şifrənin Doğrulanması və JWT İstehsalı

İstifadəçi email və şifrəsini göndərir. AuthService şifrəni tutuşdurur, xüsusi kriptoqrafik JWT Token verir və Kafka-ya "Giriş edildi" xəbəri ötürür.

1
Məlumatın Yoxlanışı
Postgres bazasından emailə görə istifadəçi tapılır. Əgər yoxdursa 401 Unauthorized qaytarılır.
PostgreSQL 5432
2
Bcrypt Hash Müqayisəsi
Gələn açıq şifrə bazadakı hash ilə bcrypt.compare() edilir. Düzdürsə davam edilir.
Bcrypt Verification
3
JWT İmzalanması
jwtService.sign({ sub: user.id, email }) ilə rəqəmsal imzalı təhlükəsiz Bearer Token yaradılır.
JWT Token (1d müddətli)
4
Kafka-ya Hadisə (Emit) 🔥
user.login mövzusuna xəbər atılır: "Filankəs sistemə daxil oldu" (təhlükəsizlik və audit loqu üçün).
Kafka Topic: user.login
auth-service.service.ts 
const token = this.jwtService.sign({ sub: user.id, email: user.email });

// Təhlükəsizlik loqu və audit üçün Kafka-ya emit edirik
this.kafkClient.emit(KAFKA_TOPICS.USER_LOGIN, {
  userId: user.id,
  timestamp: new Date().toISOString(),
});

return {
  access_token: token,
  user: { id: user.id, email: user.email, name: user.name, role: user.role }
};

🔑 Login-dən Nə Qazanırıq?

  • access_token: Müştəri bu tokeni cibinə qoyur (saxlayır). Növbəti bütün qorunan səhifələrə (bilet almaq, tədbir yaratmaq) bu tokenlə girəcək.
  • Kafka `user.login`: Bank və ya təhlükəsizlik sistemlərində olduğu kimi, kimin nə vaxt daxil olduğunu izləmək üçün Kafka vasitəsilə Təhlükəsizlik/Audit servislərinə məlumat verilir.

GET /profile — Qorunan Səhifə və JWT Guard

İstifadəçi öz məlumatlarını oxumaq istəyir. Burada KAFKA İŞTİRAK ETMİR! Niyə? Çünki bu sinxron oxuma sorğusudur.

1
Bearer Token Göndərilir
Header: Authorization: Bearer <TOKEN> ilə sorğu göndərilir.
HTTP Header
2
Passport JWT Guard Yoxlayır
jwt.strategy.ts tokenin gizli açarını (`secret`) yoxlayır, token saxta və ya vaxtı keçmiş deyilsə userId-ni çıxarır.
JwtStrategy Validate
3
Baza Oxunuşu (SELECT)
Drizzle ORM ilə yalnız həmin userId-yə aid məlumatlar oxunur və istifadəçiyə qaytarılır.
Drizzle SELECT
auth-service.controller.ts 
// Qorunan Endpoint: Yalnız etibarlı JWT Tokeni olanlar girə bilər
@UseGuards(AuthGuard('jwt'))
@Get('profile')
getProfile(@Request() req: { user: { userId: string } }) {
  return this.authServiceService.getProfile(req.user.userId);
}

🤔 Niyə Profile-da Kafka Yoxdur?

  • Qızıl Qayda: Kafka yalnız **HADİSƏ (Event)** baş verəndə istifadə olunur (yeni qeydiyyat, bilet satışı, ödəniş qəbulu).
  • Profil məlumatını oxumaq isə sadəcə bir **Göstərmə (Query)** əməliyyatıdır. Dünyada heç bir başqa servis sizin öz profilinizə baxmağınızla maraqlanmır.
  • Ona görə də bura birbaşa PostgreSQL-dən dərhal cavab qaytarılır.

⚡ Kafka Nə Qazandırır? (Arxitektura Dərsi)

Təsəvvür edin ki, sabah layihəmiz böyüdü və Mail Servisi, Bilet Satış Servisi, Statistika Servisi əlavə olundu:

❌ Kafka Olmasaydı (Köhnə Yol):

İstifadəçi "Qeydiyyat" düyməsinə basanda AuthService təkbaşına hər şeyi etməli idi:

  • 1. Bazaya yaz (50ms)
  • 2. Mail servisinə HTTP sorğusu at və cavab gözlə (1500ms)
  • 3. Statistika servisinə zəng vur (300ms)
  • 💥 Əgər Mail servisi xarab idisə, bütün qeydiyyat çökürdü və müştəri 2 saniyə ekrana baxıb gözləyirdi!

✔ Kafka İlə Event-Driven (Bizim Yolumuz):

İstifadəçi "Qeydiyyat" düyməsinə basanda:

  • 1. Bazaya yaz (50ms)
  • 2. Kafka-ya xəbər at (2ms) və dərhal istifadəçiyə cavab ver!
  • 🚀 Müştəri 50 millisaniyədə qeydiyyatdan keçir!
  • 🛡️ Mail servisi sönsə belə heç nə çökmür; sabah qalxanda Kafka-dakı növbədən mesajı götürüb emailini göndərəcək.
